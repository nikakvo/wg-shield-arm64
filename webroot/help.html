1 · what this module does

WG Shield runs a WireGuard tunnel in the kernel, with no app. It starts at boot, survives killing apps from recents, follows Wi-Fi ↔ mobile switches by itself and has a kill switch: while a tunnel is on but not working, nothing leaves the phone around it.

Android does not see a VPN. There is no VPN key icon, apps see a normal network, and nothing depends on Android's VPN service — the tunnel is plain Linux routing below it. Calls over the mobile network (VoLTE, Wi-Fi calling), SMS and MMS keep using the carrier's own networks.

Tunnels come from the official WireGuard app: export them there, import them here, then switch one on.

needs
KernelWireGuard built in (CONFIG_WIREGUARD). The installer checks it and stops if it is missing.
Tunnelswg-quick format as the WireGuard app or a VPN provider exports them (a zip or single .conf files): one [Peer], AllowedIPs with 0.0.0.0/0, an Endpoint as an IPv4 address or a host name. An IPv6 address with ::/0 carries IPv6 too. Proton VPN's configs work as downloaded.
RootSukiSU Ultra, KernelSU, APatch or Magisk (WebUI through MMRL / KSU WebUI Standalone).
Tested on a Poco F6 Pro with Xiaomi.eu HyperOS 3 (Android 16) and an android13-5.15 GKI kernel. Other ROMs name and number their networks the same way (it is Android's own netd), but that is not tested.
2 · quick start
  1. Flash the zip, reboot.
  2. WireGuard app: ⋮ → Export tunnels. The zip lands in Download.
  3. This WebUI → Tunnels → Import from Download → Import. Then delete the file with ✕: it holds your private keys.
  4. Disconnect the tunnel in the WireGuard app — one key, one tunnel.
  5. Switch a tunnel on. The route at the top shows Phone → tunnel → Internet with a moving line within a few seconds.
  6. Dashboard → Exit → Check, or open DNS Test: the server's address shows, and your own DNS resolvers.

The manager's Action button turns the last used tunnel on or off without opening the WebUI.

3 · how it works
app on the phone
↓
routing rules (before Android's own)
↓
wgs0 — the kernel tunnel, encrypted
↓
your Wi-Fi or mobile network → VPN server → internet

The pieces

One interface, wgs0, always the same name whichever tunnel is on. A routing table (51820) that sends everything into it, with an unreachable route underneath: if the tunnel disappears, traffic has nowhere to go — it never falls back to your normal connection.

Routing rules with priorities 5000–5021 sit in front of Android's (which start at 10000):

rulewhat for
5000The tunnel's own encrypted packets to the server go out through your network.
5010–5012Local destinations stay local: your Wi-Fi LAN (router, printer, SSH from a laptop), hotspot devices.
5020Everything not bound to one network → the tunnel.
5021Everything bound to the current default network (Wi-Fi or mobile) → the tunnel.

Traffic an app binds to another network keeps Android's routing — that is how IMS (VoLTE, Wi-Fi calling) and MMS keep working.

Watchdog

A background loop checks every 10 seconds (every 2 seconds during the first minute after boot): the right tunnel is loaded, Android's current default network (it gets a new number on every reconnect), the server route follows it, no rule is missing. Anything off is put back and written to the log.

At boot

If a tunnel was on when the phone went down and the kill switch is on, a blocking rule is in place before Android starts its network. Nothing leaves the phone until the tunnel is up.

4 · states and the banner
statemeaning
protectedThe tunnel is up: a handshake within the last 180 s.
connectingJust switched on, waiting for the first handshake (or for a network).
downNo handshake for more than 180 s. Kill switch on: no internet. Off: direct connection until it answers again.
pausedYou paused it, or another VPN app is connected. Direct connection.
errorThe tunnel cannot be built (file gone, kernel refused it). Direct connection — the banner says why.
offNo tunnel switched on. Your normal connection, nothing installed.
"Down" appears up to 3 minutes after the server stops answering: WireGuard itself counts a session as dead only after 180 s. Your traffic stops at once — only the label waits.

6 · tunnels and import

Every imported tunnel is a row with a switch. One at a time: switching one on switches the other off; the interface stays wgs0, only keys, server and address change. All off = your normal connection.

Import reads the WireGuard app's export zip, or single .conf files, from Download. Files that do not fit (several peers, no full tunnel, an IPv6 endpoint) are skipped and the Log says why. Importing a tunnel with a name that already exists replaces it. Names keep letters, digits, . _ -; other characters become _.

From a file the module uses only the WireGuard keys and addresses. DNS is ignored (DNS is left to the system or DNSCrypt Proxy), as are PostUp, Table and the like. A tunnel without PersistentKeepalive gets 25 s, so the health check always has fresh handshakes.

Private keys are stored in /data/adb/wg-shield/tunnels/, readable only by root. They never appear in the WebUI, the log, the status or the Report. The export in Download is readable by apps — delete it after importing.
7 · kill switch and pause

Kill switch

On (default): while a tunnel is switched on but not working, the phone has no internet at all. Off: the phone uses your connection directly while the tunnel is down, and goes back into the tunnel by itself when it answers again.

The kill switch never blocks when you turn the tunnel off, pause it, or when it cannot be built at all (error).

Pause

15 minutes, 1 hour or 4 hours on your normal connection, then the tunnel comes back. Resume now ends it early. A reboot ends a pause.

Another VPN app

While any VPN app is connected (WireGuard, Proton VPN, v2rayNG…) WG Shield steps aside and shows paused. It comes back when that VPN disconnects. That way the app stays a fallback, and two tunnels never fight over one key.

8 · with dnscrypt proxy, ipset and vpn hotspot
app DNS → DNSCrypt Proxy on the phone → tunnel → encrypted resolvers
app traffic → ipset blocklists → tunnel

DNSCrypt Proxy

WG Shield never sets DNS. DNSCrypt Proxy keeps answering every DNS query on the phone; its own connections to the resolvers simply go through the tunnel. Its IP mode decides whether the phone has IPv6 at all (see 9).

ipset

Its lists apply as always. A tunnel server must never be listed, or the tunnel cannot connect: check the server's address with ipset's Check tool, and add it to its allowlist if needed.

VPN Hotspot

VPN Hotspot (1.0-r13 or newer) reads WG Shield's status and sends hotspot devices through the same tunnel whenever it is up. Switching the server here needs nothing there. When you turn WG Shield off or pause it, hotspot devices go direct like the phone. While the tunnel connects or is down, they follow VPN Hotspot's own kill switch (no internet when it is on). Older versions of VPN Hotspot only follow Android's VPN and do not see WG Shield.

9 · ipv6 and other limits
  • IPv6. A tunnel with an IPv6 address and AllowedIPs containing ::/0 carries IPv6 too (Dashboard → IPv6: through the tunnel). A tunnel without it blocks the phone's IPv6 while it is on (unreachable), so nothing goes around it — apps switch to IPv4 at once. DNSCrypt Proxy's ipv4 mode turns IPv6 off on the whole phone; then every tunnel carries IPv4 only. Switch it to dual and the tunnel picks IPv6 up by itself within seconds.
  • The server is reached over IPv4. Proton's commented-out IPv6 Endpoint line is only another way to reach the server, not needed for IPv6 inside the tunnel — leave it commented.
  • One peer, full tunnel. Split tunnels and several peers are not supported.
  • Host-name endpoints (e.g. a home server on dynamic DNS) are looked up when the tunnel starts, with one plain DNS query to Quad9 sent outside the tunnel — before the tunnel is up there is no other way. If such a tunnel stops answering, the name is looked up again (at most once a minute), so an address change at home is followed by itself. IPv6 endpoints are not supported.
  • Same LAN on both sides. Addresses of your own Wi-Fi network always stay local. If a home VPN uses the same range as your Wi-Fi (both 192.168.1.x), devices behind that VPN cannot be reached while you are on that Wi-Fi.
  • No per-app bypass. Everything the phone sends goes through the tunnel, except traffic bound to another network (IMS, MMS).
  • Hotspot devices are routed by VPN Hotspot, not by WG Shield (see 8); they get IPv4 only.
10 · command line

Every WebUI action is a ctl.sh command. From Termux: su -c '…' with the whole command in single quotes.

sh /data/adb/modules/wg-shield/ctl.sh status          # state, tunnel, handshake
sh /data/adb/modules/wg-shield/ctl.sh list            # imported tunnels
sh /data/adb/modules/wg-shield/ctl.sh import <zip|conf>
sh /data/adb/modules/wg-shield/ctl.sh up [name]       # last used when no name
sh /data/adb/modules/wg-shield/ctl.sh switch <name>
sh /data/adb/modules/wg-shield/ctl.sh down            # normal connection
sh /data/adb/modules/wg-shield/ctl.sh pause <minutes>
sh /data/adb/modules/wg-shield/ctl.sh resume
sh /data/adb/modules/wg-shield/ctl.sh set killswitch 0|1
sh /data/adb/modules/wg-shield/ctl.sh remove <name>
sh /data/adb/modules/wg-shield/ctl.sh log [lines|clear]
sh /data/adb/modules/wg-shield/ctl.sh diag            # report, no keys

The wg tool is on the path too: su -c 'wg show wgs0' (private key hidden).

11 · troubleshooting

No internet

State down? The server does not answer and the kill switch holds. Switch to another tunnel, or pause. Stays connecting? Check the server is not blocked by ipset (see 8), then send the Report.

Paused and I did not pause it

A VPN app is connected — the banner names it. Disconnect it.

Import skipped a tunnel

The Log names the file and the reason: a key that is not a real key (for example one replaced by *****), several peers, not a full tunnel, a bad endpoint.

"Rules changed by someone else — repaired"

Something removed one of the module's routing rules; the watchdog put it back. Once is harmless. If it repeats every few seconds, another module fights over the same rules — send the Report.

Something is wrong and I need internet now

Action button in the manager (off), or ctl.sh down. If the module itself misbehaves: disable it in the manager and reboot — nothing of it stays active.

Watchdog not running

Reboot. If it stays stopped, the Log says why.

12 · files, update, uninstall
file
/data/adb/wg-shield.confSettings: active and last tunnel, kill switch (kept on update)
/data/adb/wg-shield/tunnels/Imported tunnels with their keys, root only (kept on update)
/data/adb/wg-shield/wg-shield.logLog (Clear in the Log tab empties it)
/data/adb/wg-shield-state/Runtime state, cleared at boot; status is read by the sibling modules

Update: flash the new zip, reboot. Tunnels and settings stay.

Uninstall: the tunnel and every rule are removed, then settings, log and all imported tunnels with their keys are deleted.
